# @polaris/shared-types

Canonical OpenAPI contract and generated TypeScript types for POLARIS clients (web, desktop, mobile) and the backend.

New to POLARIS? Start with the [onboarding guide](https://github.com/POLARIS-Ahmadi-OFFICIAL/.github/blob/main/ONBOARDING.md).

## Layout

- `openapi/polaris-v1.yaml`: source of truth for `/api/v1`
- `src/generated/api.ts`: generated by `openapi-typescript` (do not edit by hand)
- `dist/`: build output

## Changing the API

1. Edit `openapi/polaris-v1.yaml` and run `npm run lint:openapi`.
2. `npm run build` to regenerate types.
3. Implement the route in [backend-api](https://github.com/POLARIS-Ahmadi-OFFICIAL/backend-api) (`app/api/v1/`) and update the clients in the same change set.

## TypeScript consumers

> **Current state:** the package is not yet published to npm, and `web-frontend` / `mobile-development` do not depend on it. Each keeps a copy of `apiPath` in `lib/api-path.ts` (marked "keep in sync"). Treat this repo as the contract to check against.

To use the types directly, link the package locally:

```bash
npm install file:../shared-types
```

```ts
import { apiPath, type paths } from "@polaris/shared-types";

type Health = paths["/health"]["get"]["responses"]["200"]["content"]["application/json"];
```

## Python (backend-api)

Keep Pydantic models aligned with the same OpenAPI document:

```bash
pip install datamodel-code-generator
datamodel-codegen --input openapi/polaris-v1.yaml --output ../backend-api/app/schemas/generated.py
```

## Scripts

| Command | Description |
|---------|-------------|
| `npm run codegen` | Regenerate `src/generated/api.ts` |
| `npm run build` | Codegen + compile to `dist/` |
| `npm run lint:openapi` | Spectral lint on the spec |

CI lints and builds on every push and PR to `main`. Pushing a `v*` tag runs `npm publish` (needs an `NPM_TOKEN` secret).

## Versioning

Package semver tracks API breaking changes. Tag releases to match the backend version that implements them.
